# YURI OS Disciplined Self-Improvement Goal

Status: active
Owner: Codex/main with Shintai advisory support
Created: 2026-05-23

## Goal

Turn YURI from a powerful but still operator-steered tool stack into a durable companion control plane: clean navigation, reliable memory promotion, persistent model sessions, cyber-focused execution rails, and a repeatable improvement loop where every serious correction becomes better structure, better tests, or better recall.

This goal runs beside all product development. It is not a pause in cyber work. It is the discipline layer that keeps cyber work from creating another mess.

## Task List

### Gate 01 - Canonical Context Spine

- Keep the read cascade current: `yuri-origin` -> `SOUL` -> context registry -> index -> folder registry -> selected packet -> task-local files.
- Expand `_SYSTEM/context/context-registry.json` when new major domains appear.
- Stop broad repo crawling unless the context router says the task needs it.
- Remove active references to retired providers and early experiments after useful patterns are promoted into YURI-owned docs or skills.

### Gate 02 - Memory Promotion System

- Separate session memory, durable profile memory, project memory, cyber intelligence, and historical archive.
- Promote memory only when it has evidence, owner, use case, and retrieval path.
- Add a reviewable memory-update proposal step for sensitive user profile, strategy, or client context.
- Make `/goal`, EOT, and Rick persona context pull from curated memory, not raw protected runtime.

### Gate 03 - Goal Ledger And Task Continuity

- Keep one active visible goal for Rick via `/goal`.
- Track sub-goals as checklist items with `met`, `rating`, and evidence.
- Update goal state after major commits, Shintai dispatches, failed runs, and user corrections.
- Preserve continuity without making the user restate the same operating direction every session.

### Gate 04 - Persistent Lane Sessions

- Use persistent CLI/tmux/PTY sessions for Claude and DeepSeek when they are active collaborators.
- Forbid Claude SDK, `claude -p`, `claude --print`, and no-session-persistence prompt calls in YURI routing.
- Prefer continuous DeepSeek sessions for synthesis, EOT, and high-cache advisory work.
- Expose lane health, session status, and fallback reason through Kagami/Rick instead of hidden script behavior.

### Gate 05 - Failure Evolution Loop

- Convert real failures into one of: regression test, guardrail, routing rule, context packet update, memory proposal, or docs correction.
- Do not reward self-inflicted chaos; only promote lessons from evidence-backed failures.
- Keep a rollback path for architecture changes.
- Make repeated user corrections impossible to miss twice.

### Gate 06 - Registry And Storage Hygiene

- Every durable folder and important artifact must have a classification path.
- New docs, scripts, configs, reports, research, and skills must land in the right YURI-owned location.
- Generated/runtime files stay out of Git unless explicitly promoted.
- Protected surfaces remain sealed and are accessed only through wrappers or summaries.

### Gate 07 - Cybersecurity Product Spine

- Translate every cyber research finding into one of: watch-only, lab scenario, scanner rule, guardrail, client report section, or implementation task.
- Keep offensive research tied to owned labs, authorization, and defensive deliverables.
- Build security capability from proof surfaces, not claims.
- Prioritize Upgreat-ready evidence: agent/MCP security, memory/RAG security, repo/supply-chain scanning, threat intel, and guardrail proof.

### Gate 08 - Release Proof

- A feature is not done because it sounds good.
- Ship only after syntax, tests, secret scan, protected-path scan, and relevant runtime checks pass.
- Keep dirty worktree reports scoped so unrelated runtime noise does not hide real source changes.
- Commit small enough slices that future Rick can understand what changed without archaeology.

## Disciplined Cleanup Standard

Disciplined cleanup means continuous entropy control while building. It is not beautification.

It includes:

- Naming cleanup: one canonical name per active concept.
- Folder cleanup: no random root-level tool dumps or duplicated provider trees.
- Registry cleanup: every important path classified before models depend on it.
- Context cleanup: models load the smallest correct packet before reading files.
- Memory cleanup: durable memory is promoted, not sprayed.
- Runtime cleanup: local caches, credentials, logs, and generated output stay out of source truth.
- Dispatch cleanup: every model lane has a real owner, cost posture, tool posture, and health state.
- Test cleanup: every fixed failure gets a regression when the risk is likely to recur.
- Documentation cleanup: current docs outrank old handoffs; old docs must be marked historical or removed from active navigation.
- Commit cleanup: source changes, runtime noise, and protected data are never mixed into the same commit.

## Working Forecast

- Short horizon: YURI becomes a reliable project companion when context, memory, and lane sessions stay clean for multiple consecutive sprints.
- Mid horizon: YURI becomes a symbiotic cyber work system when cyber labs, threat intel, and guardrails are wired into the same memory and release gates.
- Long horizon: YURI becomes an almost companion-like operating partner when it can preserve goals, interrupt drift, route specialists, remember user intent, and prove its work without manual stitching.

## Non-Negotiables

- No protected-path reads or writes outside approved wrappers.
- No Claude one-shot prompt calls.
- No unclassified durable artifacts.
- No silent memory mutation.
- No resurrecting retired provider/platform surfaces.
- No cybersecurity claims without owned-lab proof, source-backed intelligence, or client-safe evidence.
