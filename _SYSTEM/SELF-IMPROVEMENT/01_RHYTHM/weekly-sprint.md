# Weekly Sprint Protocol

> Sunday-night planning. Nocturnal schedule. One sentence wins.

---

## When: Sunday Night, 21:30-22:00

Sunday during the night block. Takes 30 min max. Do it before starting any Sunday deep work.

## Practice: The Sprint File

Keep a single markdown file for the current week: `_SYSTEM/SPRINTS/sprint-YYYY-WW.md`

```
# Sprint: 2026-W19 (May 4-10)

## Goal
"Deliver C2MovieZ interview package (grade + sound + titles) and complete 
planzerfilms location scout + treatment."

## Tasks
- [ ] HARD: C2MovieZ — grade pass + titles export (8h est, break into 3 nights)
  - Mon night: grade pass scenes 1-5
  - Tue night: grade pass scenes 6-10
  - Wed night: titles + final render
- [ ] EASY: Organize planzerfilms reference folder (1h)
- [ ] EASY: Send invoice for April work (15 min)

## Capacity
Available: Mon-Fri (5 night blocks, ~5h each = 25h)
Estimated: 9.5h work + 2h buffer = 11.5h
Status: ✅ On track

## Retro (Friday night)
- What went well: Grade pass faster than expected — kept parallel structure
- What didn't: Underestimated title template creation
- Adjust for next week: Block 30 min for template setup separately
- Energy notes: Tuesday was bad, switched to fallback early — accept this
```

---

## Sprint Goal Format

**One sentence.** Measurable. Completable by Friday.

Good:
- *"Deliver graded + titled C2MovieZ interview package."*
- *"Complete planzerfilms location scout deck and treatment document."*
- *"Solve 10 leetcode mediums across 3 categories, typed up with explanations."*

Bad:
- *"Make progress on C2MovieZ"* → What counts as done?
- *"Work on multiple client projects"* → Which one is priority?
- *"Get better at color grading"* → Not measurable in a week

## The 3-Task Maximum Rule

**One hard task + two easy tasks per sprint.** That's it.

| Type | Description | Example |
|------|-------------|---------|
| HARD | Deep creative/technical work, 4-10h | Grade pass, code module, script draft |
| EASY | <2h, admin-adjacent | File organization, invoice, reference gathering |
| EASY | <2h, maintenance | Server updates, email cleanup, gear checklist |

If you finish the hard task by Wednesday, you can add another. Otherwise, the sprint is full.

## Capacity Estimation

- Each night block: ~5h of genuine productive time (after breaks, transition, wind-down)
- Subtle obstacles: tired nights (1-2 per week), client calls, social events
- **Rule:** Estimate your capacity, then subtract 20%. Whatever's left is real.
- If a task spans multiple nights, break it into nightly units before the sprint starts.

| Nights Available | Real Capacity |
|:----------------:|:-------------:|
| 5                | ~20h          |
| 4                | ~16h          |
| 3                | ~12h          |

## End-of-Week Retrospective (Friday Night)

Five minutes. Answer these:

1. **What did I complete this week?** (list deliverables, even small ones)
2. **What blocked me?** (external: client delay, missing asset; internal: energy, distraction)
3. **What went better than expected?** (this is important — you need to know your strengths)
4. **What adjustment for next week?** (one change only — don't overhaul the system)
5. **Energy score:** Mon__ Tue__ Wed__ Thu__ Fri__ (1-10 each)

Log this in the sprint file. Over 4-5 weeks, patterns will emerge — that's the gold.
