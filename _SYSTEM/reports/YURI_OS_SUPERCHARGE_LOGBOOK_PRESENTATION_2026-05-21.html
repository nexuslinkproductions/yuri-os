Old failure

Daemon rows showed stale last-run values even while PID was alive.

`launch-readiness-nightly`, `lane-memory-prune`, and `ollama-kv` needed different repair semantics.

New split

Process liveness: PID and launchd status.
Last exit: crash or clean completion evidence.
Activity: stdout mtime only when relevant.
State freshness: state marker age, separate from process health.
Schedule expectation: `live`, `on_schedule`, `missed_window`, `on_demand`.
