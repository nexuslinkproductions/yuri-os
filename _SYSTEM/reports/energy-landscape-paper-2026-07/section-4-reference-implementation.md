# Section 4: Reference Implementation — YURI

Section 3's mechanism — a scalar potential U gated by strict descent — is not only describable; it is built. The reference implementation is YURI, an independently developed single-operator control plane created by the paper's author as a working substrate for the author's own agent-orchestration workflows. YURI is not a published platform and not a multi-tenant product. It is one operator's working environment, and it happens to instantiate the proposal of Section 3 in a form that runs, tests, and produces verifiable numeric output.

The core of the energy implementation lives in a single module: `_SYSTEM/Scripts/math/yuri-energy.mjs`. The module exports four surfaces: `computeU()`, which evaluates the scalar potential over a state snapshot; `computeDeltaU()`, which computes the signed difference between two states; `gateProposal()`, which combines both evaluations into an accept/reject decision; and `DEFAULT_WEIGHTS`, the operator-tunable weight vector. Section 3's pseudocode used underscore notation (`KL_divergence`, `log_loss`) for readability — the actual implementation uses camelCase throughout, consistent with the surrounding math kernel. The canonical import is `import { computeU, computeDeltaU, gateProposal, DEFAULT_WEIGHTS }`.

`DEFAULT_WEIGHTS` encodes the default composition across the six primitives: protected-path violations and promotion-ladder inversions carry high penalty weight; entropy and KL divergence carry moderate positive weights; verified-evidence credit carries a negative weight that rewards epistemic progress. These defaults are hand-tuned for a single-operator deployment, not learned from data, and not validated at production scale. The weight surface is intentionally exposed — the mechanism is designed to be operator-configured, and `DEFAULT_WEIGHTS` is the starting point rather than the final word.

The worked example that ships with the module runs two scenarios. Scenario A models a well-behaved transition: a claim that gains verified evidence support. The gate evaluates `computeDeltaU()` and returns `ΔU = -0.261167305`. The component breakdown shows a small entropy rise (+0.015) — the distribution momentarily widens as new evidence arrives — outweighed by a larger drop in KL divergence (-0.176) as claimed and verified distributions converge. The verified-evidence credit (-0.100) adds a further descent contribution. The gate accepts: the transition is a certified non-worsening step, and the dominant cause of descent is traceable.

Scenario B models a protected-path violation. An agent proposes a state change that reads a path outside its sanctioned scope. The `protectedPathViolations` term fires at full penalty weight, dominating all other components. The gate returns `ΔU = 100` — a sharp, unambiguous energy increase — and rejects the transition before it takes effect. The rejection is issued without consulting the model that generated the proposal; the gate operates on the state description alone. The violation is detectable, auditable, and blocked at the control-plane layer, not at the model layer.

Every result envelope produced by `computeU()`, `computeDeltaU()`, and `gateProposal()` carries two fields that reflect the implementation's epistemological posture: `advisory_only: true` and `local_truth_claim: false`. The `advisory_only` flag is YURI's architectural commitment: energy evaluations are inputs to a decision, not substitutes for deterministic local evidence. A gate result of `accept: true` means the transition clears the energy condition — it does not certify that the underlying claim is factually correct, and it does not override a hard block from a higher-authority gate. That distinction is preserved by design and enforced by the flag's presence in every response envelope.

The test suite covers 28 cases: unit coverage of each primitive, integration coverage of the composition rule, a CLI end-to-end that confirms both scenarios produce the stated output, and a realistic three-step descent trace that verifies monotonic U decrease across a multi-step sequence. All 28 tests pass. The implementation is, in that sense, complete. The gate is not yet wired into the live dispatch layer — calling `gateProposal()` from the agent-routing infrastructure is the integration step that converts this from prototype to operational. At this scale, that step is single-operator work, not a paper contribution, and it is noted here for scope transparency.

Section 5 examines the design trade-offs this implementation leaves open: where hand-tuned weights are sufficient, where they are not, and what the honest boundary between the energy-gating guarantee and the broader goal of agent coherence actually is.
