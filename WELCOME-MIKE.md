## 1. What Yuri actually is

Not a chatbot. An **external nervous system**. You brain-dump — messy, nonlinear, half-formed — and it decodes the pattern, routes the work to the right lane (Codex / DeepSeek / local models / Claude lanes), builds, verifies against real evidence, and *remembers across sessions*. Messy input is the expected input. You direct; it executes and checks.

## 2. Get set up

You already have the clone (Marcel added you to the private `yuri-os` repo). To bring it to life:

1. **Node** — make sure you have Node 18+ (`node -v`).
2. **Claude Code** — this repo is driven through Claude Code (CLI / VS Code extension). Marcel walks you through auth.
3. **First boot** — open the repo, start a Claude session. A `<yuri-brain>` block loads automatically: persona, rules, live system state, and the operator cognitive contract. That's why it already "gets" how you work.
4. **Don't run the frozen models** — see the HARDWARE notes in the brain block; some local models are memory-frozen on certain machines.

## 3. How to operate it (the 4 that matter)

1. **Just talk.** Shotgun bursts of ideas are fine — it decodes structure first, asks only when something is genuinely ambiguous.
2. **Give it the goal, not the keystrokes.** It plans, routes, and verifies. Let it.
3. **When it challenges you once, listen.** It's an adversarial ally by design — one concern, one piece of evidence, one recommendation. Then it respects your call.
4. **Trust the memory.** It externalizes what landed where, what's live, what's parked. You shouldn't have to ask "where did that go."

## 4. The rules that keep it safe

- It will **not commit or push** without you saying so.
- It will **not read secrets** or touch protected paths.
- It treats anything outward-facing (publishing, sending) as needing your confirmation.
- It stays inside owned/authorized labs for any security work.
