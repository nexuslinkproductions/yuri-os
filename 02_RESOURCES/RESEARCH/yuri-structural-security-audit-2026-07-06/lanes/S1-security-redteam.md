## CONFIRMED vs PLAUSIBLE

**CONFIRMED (traced in code, evidence above):**
- #1 hook-bypass architecture gap (yuri-z-brain.py is outside the Claude Code hook chain) — traced via `.claude/settings.json` matcher semantics + the file's own standalone regex.
- #2 confirm-gate is syntax-only, not taint-aware — traced via `_is_critical_call`/`_CRITICAL_BASH`.
- #3 `write_file` new-file-is-routine — traced via the exact conditional at line 380-382.
- #4 protected-path denylist gaps — traced via the literal `PROTECTED` tuple, verified locally against real dotfile paths.
- #5 fleet-lane `PROTECTED_TARGETS` missing `.git/` — traced via `yuri-safety-core.mjs` lines 13-23.
- #6 screen-context `/act` NOT wired — traced via full `TOOLS` array read + repo-wide grep for callers.
- #7 hook literal-match residual risk — traced via `bash-security-guard.js` token-Set logic; corroborates the sibling H2 audit's own flagged residual risk.

**PLAUSIBLE (design-level concern, not exploited/traced end-to-end):**
- #2's SPECIFIC exploit chain (a crafted PDF containing an instruction that gets GLM to emit a non-matching-pattern critical action) — the MECHANISM is confirmed (untrusted content flows into model context and the model's own output is the only thing screened), but no live PDF was crafted and run through the pipeline.
- #8's multi-step chaining exploit — the STATELESS per-call classification is confirmed; the specific "new script + chmod + LaunchAgent" chain is a plausible construction, not executed.

## Top 3 Highest-Leverage Hardening Moves

1. **Collapse to ONE gate.** yuri-z-brain.py's bash/write/edit tool execution should call the SAME `evaluateToolCall` (`_SYSTEM/Scripts/policy/yuri-safety-core.mjs`) that `llm-lane.mjs` already uses, instead of maintaining a second, narrower, hand-rolled regex/tuple set. Right now YURI has at minimum 3 independent protected-path implementations (Claude Code hooks, `yuri-safety-core.mjs`, yuri-z-brain.py's own) that will silently drift out of sync — this audit already found the drift (finding #4/#5).
2. **Taint the pipe, not just the output.** Every tool whose result can contain attacker-influenceable text (`read_doc`, a future `screen-context` read, `fetch_url`, a fleet-lane peer's returned text treated as "evidence") should mark that content as UNTRUSTED in the next turn's context, and the confirm-gate should escalate ANY subsequent critical-adjacent tool call in the same turn/session window that plausibly derives from it — not rely on the command syntax alone matching a fixed regex.
3. **Make unattended mode structurally safer than attended mode, not the same.** Today the overnight/autonomous surface has the SAME tool access and the SAME regex gates as the attended, human-in-the-loop mode — it just loses the human backstop that catches what the regex misses. Ship an explicit reduced-capability profile (read/xref/remember only, or a stricter allowlist) that arms automatically when no human has spoken to Yuri within a configurable window, rather than treating "human isn't listening" as a a non-event for the safety model.
