03 · The real work — the canonical DataPoint model (Rust)

The connectors are thin. The hard build is the math layer. Today's Rust kernel is Lead-centric (LeadFeatures, lead_score, attribute on loose (String,f64) tuples) with NO canonical Metric/DataPoint entity. This is the from-scratch moat extension.

Reuse (don't reinvent)

Money{Decimal,ISO-4217}→(i64 cents, TEXT) at nexus-engine/crates/nexus-core/src/money.rs — matches the GA4 / Google Ads cost_micros dual-currency + integer-minor-units pattern exactly. Time-decay attribute() already in nexus-metrics/src/lib.rs. clamp01 / brier_score / anomalies all reusable.

Build new

A GA4-style EVENT model: typed ValueUnion, dimensions-first-class. Two entities emit into ONE time-series table. Re-type attribute() to consume a typed Touchpoint instead of (String,f64). channel_prior() becomes data-driven config, not a hard-coded match.

The DataPoint contract (one table, organic + paid)

{ entity_id, entity_type(post|profile|ad_account|campaign|ad_group|ad), platform(meta|google|microsoft), channel_type(organic|paid), metric_name, value: ValueUnion{ int(i64) | float(f64) | cents_native(i64)+currency_native(ISO-4217)+cents_eur(i64) | ratio(f64) | text }, dimensions: JSON (campaign_id, country, device, age, gender, ...), period(day|month|lifetime|event), metric_kind(counter|ratio|duration|currency|unique_count), aggregation_rule(sum|recompute_from_num_denom|non_aggregatable), captured_at_utc_micros }

Currency: EUR reference

Dual-column value_native_cents + currency_native + value_eur_cents, FX-locked at ingest. EU-hosted, DACH SMBs → EUR (not USD).

Aggregation rules

counter→SUM; ratio→store num+denom, RECOMPUTE on aggregate; unique_count→NON-aggregatable (prevents SUM(daily reach) inflating monthly reach 3–5×); currency→SUM with normalization.

Silent-zero defense

IG / post-Nov-2025 FB return empty sets, not zeros. Connector must assert each requested field came back and fail-closed on deprecated metric names (Meta deprecated a wave Nov 15 2025). Empty-set aggregated as 0 corrupts engagement-rate denominators.

05 · Multi-tenant + the fairness scheduler

Baked day one. The shared-quota reality makes the scheduler non-optional, not nice-to-have.

orgId / customerId on every row

From the first migration — Postiz shape. Postgres RLS enforces isolation (the MASTER-PLAN §11 single largest technical risk). The MCP gateway maps session tokens → per-subscriber provider tokens (DPoP-bound, short-lived).

Priority-queue scheduler (not round-robin)

Keyed by (tenant_id, freshness_window, metric_kind) with per-tenant fairness weights. Meta per-app + Google per-developer-token quotas are shared across all tenants — without fairness scheduling, one heavy tenant starves everyone. Climb Google to Basic (15,000 ops/d) before multi-tenant READ scales.

07 · Security musts (binding, carried from research)

S256 PKCE verbatim

OAuth 2.1 REQUIREMENT. Carry _pkce() into every OAuth2 connector. Gmail is a near-clone; Meta uses webview-fragment intercept (loopback impossible), not a PKCE change.

Rust keyring, not security-CLI

Cross-platform; secret out of Python's reachable FS. com.nexuslink.app.<provider> per connector.

Token-broker, never pipe

Vault RT locally → mint DPoP-bound (RFC 9449) 5–15 min access tokens → agent proves possession per request. Resale-critical.

Own every refresh cadence

Google (Testing-mode 7-day RT death until published) · Meta/IG (~50-day beat vs 60-day wall; System User for resale). Atomic: write new RT before using old.

State in keyring + 5-min TTL

Crash/restart fails-closed (RFC 8252 §10).

Tiered + incremental scopes

Read tier first; messaging-write (reply) added on first connect. Narrows Meta App-Review use-case statements.
