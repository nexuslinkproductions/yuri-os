04b · Fleet hardening — the cosmetic exit-1 is fixed

You flagged the false exit-1 on the GLM dispatch. Root-caused and fixed at the source — done this session, verified, 60/60 tests green. It was two compounding bugs, not one.

ROOT CAUSE

lane-dispatch.mjs isBad() checked exit code before the out-file. A lane that wrote its complete, labeled result to --out and then exited non-zero (transport cleanup after the last byte) was judged "bad" and retried — and the empty retry truncated and clobbered the good output with a failure record. The fleet then reported a failure for work that had actually succeeded.

FIX (2 layers)

1. lane-dispatch.isBad() — a non-empty --out is now the authoritative success signal, regardless of exit code; no needless retry, no clobber (matches the file's own contract).
2. contract-conformance.classifyLaneOutcome() — shared output-first classifier both fleets use: complete + valid non-F label ⇒ success (flagged degraded if exit was non-zero); empty / sentinel / F-label ⇒ fails loudly. Fleet exit code now reflects work outcome, not raw child exit.

Verified: 9 classifier cases + 3 real-seam lane-dispatch regression tests (a complete-output-then-exit-1 lane is NOT retried and its --out survives intact) + a live 3-lane GLM smoke returning exit 0. Files: _SYSTEM/Scripts/lane-dispatch.mjs, contract-conformance.mjs, glm-fleet.mjs, ollama-fleet.mjs + 2 test files.
