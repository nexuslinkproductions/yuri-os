GOAL: build YURI's cross-domain transfer engine — the mechanism that actively scours UNRELATED domains for transferable solutions, so a generalist + curated corpus beats narrow niche LLMs without heavy compute. Marcel's core operating thesis, now an explicit build target.
THESIS (owner, load-bearing): innovation comes from cross-referencing across unrelated domains — "can I take a mechanism from sector A and translate it into completely unrelated sector B to solve a problem?" (Marcel's physics-math -> energy/memory idea arose exactly this way; he calls the act itself philosophy). Modern training — school, niche specialization, the whole crop of niche expert LLMs/SLMs — forces narrow-lane thinking; domains hunt for answers only INSIDE themselves instead of importing a mechanism from another horizon. Every horizon can improve a different domain; most experts can't see it because they were trained narrow. The database exists to make cross-referencing ACTIVE and the possibility-space effectively infinite.
HALLUCINATION = POTENTIAL (reframe, owner): hallucination / rule-breaking is not purely bad — it is the substrate of creativity (the human-owned part). The sin is not generating a wild idea; it is ASSERTING an unverified idea to the user AS FACT (that is the hallucination/lying failure). Resolution: maximal free divergence at the BOTTOM of the promotion ladder (hypotheses), strict discipline at the TOP (verified fact). Anti-hallucination and creativity are the SAME promotion ladder (claim-integrity-gate PROMOTION_STATES) viewed from both ends — free to imagine, disciplined to assert.
WHERE (build, reuse-first): GENERALIZE the existing FAILURE cross-referencer `_SYSTEM/Scripts/self-improvement/cross-reference.mjs` (its TAXONOMY rule = "tag the mechanism, not the topic; reuse the same tag across different domains when the shape is the same") + `cross-reference-taxonomy.md` — from failure-shapes to SOLUTION / MECHANISM-shapes. Mechanism-keyed retrieval over the existing FTS5 corpus (`ai search`, ~38k docs): cross-domain transfer is a RETRIEVAL problem (cheap), NOT a bigger-model problem. Forced-diversity retrieval (cap hits per domain, require N distinct domains in the candidate set) prevents over-scoping one lane. The polymathic-transfer RULE already lives in SOUL.md (name source domain / target domain / shared mechanism / mismatch / confidence) — the missing piece is the TOOL that feeds it corpus candidates instead of relying on whatever the model happens to recall. Generated transfers are HYPOTHESES -> mismatch-check + test -> promote through the claim-ledger / computeU ladder before being asserted as fact.
EXPAND-WITHOUT-COMPUTE (the meta-point): put the breadth in the CORPUS + retrieval discipline, not in the weights. A generalist model + a mechanism-tagged cross-domain retrieval layer beats training niche specialists — infinitely broad, light compute. This is why Marcel's approach is more viable than the niche-LLM crop.
HARD PART (adversarial): the cost is CURATION (mechanism-tagging the corpus), NOT compute — sloppy tags return noise; consistent with the curate-don't-scrape thesis. Ungated transfers = confident cross-domain bullshit; the verify-before-promote step is NON-optional or the engine becomes a plausible-nonsense generator (the same hallucination failure).
