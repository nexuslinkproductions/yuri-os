GOAL: a clean, deterministic, mathematically-governed FILING SYSTEM for all of YURI. Right now too much is
generated and thrown into "appropriate pools" that aren't clean/structured enough (research docs, /tmp scratch,
lane outputs, memories, reports). At YURI's current size this breaks down — everything needs CLEAR STRUCTURE +
ORDER. Every artifact (including temp files) must be directly ASSESSED on creation and STORED PROPERLY.

THE MATH ANGLE (Marcel: "this we can solve mathematically aswell"): a deterministic PLACEMENT FUNCTION —
classify any artifact (type, surface, owner-organ, lifecycle stage) → its canonical location. Candidate mechanisms:
content/path classification (reuse yuri-match cross-surface recall + the id-bridge canonical-id), graph centrality
(yuri-navigate: which organ owns this), entropy/dedup (near-duplicate detection so the same thing isn't stored
twice), hazard-decay lifecycle (temp → archive → purge by age/value, like the OpenProcess hazard term), and a
schema/type-algebra for "what kind of artifact is this + where do its kind live." Deterministic + auditable.

SCOPE includes: research outputs (02_RESOURCES/research), /tmp scratch + lane dispatch files, memories,
reports, generated docs, telemetry logs. Everything gets a home + a lifecycle, nothing orphaned.

CONNECTS TO: the auto-registration vision ([[circuitry-auto-registration-regen-vision]] — everything that joins
YURI's wiring auto-registers) and the convergence ([[originator-convergence-all-surfaces-as-nodes]]). The filing
system is the STORAGE side of "everything assessed + placed"; auto-registration is the WIRING side. Same spine.
