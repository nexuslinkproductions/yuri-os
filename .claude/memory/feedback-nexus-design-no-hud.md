RULE  Marcel dislikes the YURI HUD / Kagami visual design systems (the `--yuri-hud-*` and `--yuri-kagami-*` token namespaces in `_SYSTEM/DESIGN.md`) — do NOT apply those aesthetics to his deliverables. Use `design-master` as METHOD only (its intake gate, design-intelligence/verify/promote loop, quality bar) and INVENT a fresh design language per surface, grounded in the actual brand. For Nexus Link work, derive the system from the real Nexus Link identity (Celtic-knot logo set at `03_NEXUS-LINK/Identity/NLP LOGO/`), never from the YURI HUD tokens.

DEFINITION OF "MOTION" (Marcel's): motion = ANIMATED, MOVING PARTS — animated graphs / diagrams / visual models (data-viz that animates in and moves), scroll-driven animation + reveals + parallax, a custom INTERACTIVE CURSOR, hover/interaction reactivity, real motion-design polish (AE-grade, feels composed). Motion is NOT loaders / spinners / progress curves. Do NOT equate motion with `math-curve-loaders` — that is the wrong tool and caused confusion; do not bring it up as "the motion."

WHEN  Any visual/design/HTML/presentation/brand deliverable, especially client-facing or Nexus Link surfaces.

DO  Run the design-master intake (answer/map the 10 design questions incl. emotional temperature); invent a bespoke palette/type/component system from the brand; embed the real brand logo; build it ALIVE with genuine motion design (animated visual models/charts/diagrams, scroll-driven motion, interactive cursor, reactive hovers); and give dense data real information architecture (sort / filter / search / progressive disclosure / animated viz).

DONT  Force `--yuri-hud-*` / `--yuri-kagami-*` tokens or the HUD/cyber look. Don't ship a stale static document. Don't reduce "motion" to loaders/spinners. Don't hand-roll a generic editorial default that skips design-master.

STYLE  Premium, alive, motion-designer-grade — feel composed, not coded.

WHY  Marcel rejected the HUD/Kagami aesthetic and the loader-as-motion framing explicitly; he wants invented-per-brand design via the design-master process, with motion meaning real animated/moving/interactive parts.
